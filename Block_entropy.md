Теперь напишем полноценную функцию `block_entropy` на C и разберём её практически построчно, как мы делали с `conditional_entropy`.

Сохраним твой стиль программирования: понятные названия переменных, обычные циклы `for`, проверки через `if`, динамическое выделение памяти через `malloc` и `realloc`.

Сразу отмечу главное отличие от предыдущей функции: здесь нам не нужно хранить контексты и следующие за ними символы. Мы будем хранить **уникальные блоки и количество их появлений**.

# **1. Что должна делать функция**

Допустим, исходная последовательность:

```
size_t sequence[] = {1, 2, 1, 2, 1, 2};
```

Длина блока:

```
order = 2;
```

Наша функция должна сформировать перекрывающиеся блоки:

```
(1, 2)
(2, 1)
(1, 2)
(2, 1)
(1, 2)
```

Затем подсчитать их частоты:

| Блок   | Количество |
| ------ | ---------- |
| (1, 2) | 3          |
| (2, 1) | 2          |

И рассчитать энтропию:

\\[ B_2=-\frac35\log_2\frac35-\frac25\log_2\frac25 \\]

Результат:

\\[ B_2\approx0.971\text{ бит/блок} \\]

# **2. Структура для хранения блоков**

Прежде чем писать саму функцию, нам нужно определить структуру, в которой будут храниться блоки.

Добавь её в `entropy.c` перед функцией `block_entropy`:

```
typedef struct
{
    size_t *block;
    size_t count;
} BlockFrequency;
```

Разберём её.

```
typedef struct
```

Объявляем новую структуру.

```
size_t *block;
```

Указатель на массив элементов, из которых состоит конкретный блок.

Например, если длина блока равна 3, то в памяти будет храниться:

```
block -> [1, 2, 1]
```

Почему указатель, а не обычная переменная `size_t`?

Потому что блок может содержать разное количество элементов. Нам нужна динамическая память.

```
size_t count;
```

Количество появлений этого блока в исходной последовательности.

Например:

```
block = [1, 2]
count = 3
```

Это означает, что блок `{1, 2}` встретился три раза.

В итоге массив структур будет выглядеть примерно так:

**Массив BlockFrequency**

**Элемент 0**

block:

**[1, 2]**

count:

**3**

**Элемент 1**

block:

**[2, 1]**

count:

**2**

В массиве находятся только уникальные блоки. Повторные блоки увеличивают count.

# **3. Полная функция на C**

Вот реализация, которую будем разбирать:

```
int block_entropy(const size_t *sequence, size_t length, size_t order, double *result)
{
    if (sequence == NULL) return -1;
    if (length == 0) return -1;
    if (order == 0) return -1;
    if (order > length) return -1;
    if (result == NULL) return -1;

    *result = 0.0;

    BlockFrequency *blocks = NULL;

    size_t block_count = 0;
    size_t block_capacity = 0;

    size_t total = length - order + 1;

    for (size_t i = 0; i < total; i++)
    {
        size_t *new_block = malloc(order * sizeof(size_t));

        if (new_block == NULL)
        {
            goto cleanup;
        }

        for (size_t j = 0; j < order; j++)
        {
            new_block[j] = sequence[i + j];
        }

        size_t block_index = block_count;

        for (size_t j = 0; j < block_count; j++)
        {
            if (memcmp(blocks[j].block, new_block, order * sizeof(size_t)) == 0)
            {
                block_index = j;
                break;
            }
        }

        if (block_index < block_count)
        {
            blocks[block_index].count++;

            free(new_block);
        }
        else
        {
            if (block_count == block_capacity)
            {
                size_t new_capacity;

                if (block_capacity == 0) new_capacity = 4;
                else
                {
                    if (block_capacity > SIZE_MAX / 2)
                    {
                        free(new_block);
                        goto cleanup;
                    }

                    new_capacity = block_capacity * 2;
                }

                if (new_capacity > SIZE_MAX / sizeof(BlockFrequency))
                {
                    free(new_block);
                    goto cleanup;
                }

                BlockFrequency *temp = realloc(
                    blocks,
                    new_capacity * sizeof(BlockFrequency)
                );

                if (temp == NULL)
                {
                    free(new_block);
                    goto cleanup;
                }

                blocks = temp;
                block_capacity = new_capacity;
            }

            blocks[block_index].block = new_block;
            blocks[block_index].count = 1;

            block_count++;
        }
    }

    double entropy = 0.0;

    for (size_t i = 0; i < block_count; i++)
    {
        double probability = (double)blocks[i].count / (double)total;

        entropy -= probability * log2(probability);
    }

    *result = entropy;

    for (size_t i = 0; i < block_count; i++)
    {
        free(blocks[i].block);
    }

    free(blocks);

    return 0;

cleanup:

    for (size_t i = 0; i < block_count; i++)
    {
        free(blocks[i].block);
    }

    free(blocks);

    return -1;
}
```

В начале `entropy.c` должны быть подключены необходимые библиотеки:

```
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <math.h>
```

`stdint.h` нужен для `SIZE_MAX`, `string.h` — для `memcmp`, `math.h` — для `log2`, а `stdlib.h` — для работы с динамической памятью.

# **4. Подробный разбор функции**

## **Шаг 1. Заголовок и входные параметры**

```
int block_entropy(const size_t *sequence, size_t length, size_t order, double *result)
{
```

Функция принимает четыре параметра.

| Параметр   | Что означает                             |
| ---------- | ---------------------------------------- |
| `sequence` | Исходная последовательность чисел        |
| `length`   | Количество элементов последовательности  |
| `order`    | Длина анализируемого блока               |
| `result`   | Адрес переменной, куда запишем результат |

Почему возвращаем `int`, а не `double`?

Потому что функция должна сообщать об успешном выполнении или ошибке:

- `0` — функция выполнилась успешно;
- `-1` — произошла ошибка.

А само значение энтропии мы передаём через `result`.

## **Шаг 2. Проверка входных данных**

```
if (sequence == NULL) return -1;
```

Проверяем, существует ли исходная последовательность.

Если указатель равен `NULL`, работать с массивом нельзя.

```
if (length == 0) return -1;
```

Проверяем, что последовательность не пустая.

У пустой последовательности невозможно сформировать блоки.

```
if (order == 0) return -1;
```

Проверяем, что длина блока не равна нулю.

В отличие от `conditional_entropy`, здесь нулевой порядок недопустим.

Почему? Потому что блочная энтропия рассматривает блоки, состоящие хотя бы из одного элемента.

```
if (order > length) return -1;
```

Проверяем, что длина блока не превышает длину всей последовательности.

Например:

```
length = 5
order = 6
```

Такой блок сформировать невозможно.

Но если `order == length`, ошибка не возникает. В этом случае мы получим ровно один блок.

```
if (result == NULL) return -1;
```

Проверяем, что существует указатель, через который можно вернуть результат.

```
*result = 0.0;
```

Обнуляем результат перед вычислениями.

Так при ошибке в переменной результата не останется случайное старое значение.

## **Шаг 3. Подготовка массива блоков**

```
BlockFrequency *blocks = NULL;
```

Создаём указатель на массив структур `BlockFrequency`.

Пока память не выделена, поэтому присваиваем `NULL`.

В дальнейшем здесь будут храниться все уникальные блоки.

```
size_t block_count = 0;
```

Количество уникальных блоков, которые мы уже нашли.

Например, если обнаружены блоки:

```
(1, 2)
(2, 1)
```

то `block_count` будет равен 2.

```
size_t block_capacity = 0;
```

Вместимость массива `blocks`.

Помни, что `block_count` и `block_capacity` — разные вещи:

- `block_count` показывает, сколько элементов реально записано;
- `block_capacity` показывает, сколько элементов помещается в выделенной памяти.

Это тот же принцип, который мы применяли в `conditional_entropy`.

## **Шаг 4. Вычисление количества блоков**

```
size_t total = length - order + 1;
```

Одна из самых важных строк функции.

Она вычисляет, сколько перекрывающихся блоков можно получить из исходной последовательности.

Почему именно такая формула?

\\[ N\_{\text{блоков}}=length-order+1 \\]

Возьмём пример:

```
sequence = 1 2 1 2 1 2
length = 6
order = 2
```

Получаем:

\\[ 6-2+1=5 \\]

Значит, мы можем сформировать пять блоков.

Начальные индексы этих блоков:

```
0
1
2
3
4
```

Последний блок начинается с индекса 4 и содержит элементы с индексами 4 и 5.

Именно поэтому мы прибавляем единицу.

## **Шаг 5. Цикл формирования блоков**

```
for (size_t i = 0; i < total; i++)
{
```

Начинаем цикл, который будет проходить по всем возможным начальным позициям блоков.

Переменная `i` — индекс первого элемента текущего блока.

Например, при `order = 2`:

| i | Начало блока |
| - | ------------ |
| 0 | Элемент 0    |
| 1 | Элемент 1    |
| 2 | Элемент 2    |
| 3 | Элемент 3    |
| 4 | Элемент 4    |

На каждой итерации мы создаём новый блок.

```
size_t *new_block = malloc(order * sizeof(size_t));
```

Выделяем динамическую память для текущего блока.

Почему умножаем на `sizeof(size_t)`?

Потому что нам необходимо выделить память под `order` элементов типа `size_t`.

Например, если `order == 2`, выделяем память под два элемента.

```
if (new_block == NULL)
{
    goto cleanup;
}
```

Проверяем, удалось ли выделить память.

Если нет, переходим к общей очистке.

Это необходимо, потому что к этому моменту массив `blocks` уже может содержать ранее найденные блоки.

## **Шаг 6. Копирование элементов в новый блок**

```
for (size_t j = 0; j < order; j++)
{
    new_block[j] = sequence[i + j];
}
```

Здесь мы копируем элементы исходной последовательности в отдельный массив `new_block`.

Давай рассмотрим конкретный пример:

```
sequence = {1, 2, 1, 2, 1, 2};
order = 2;
```

Когда `i == 0`, цикл выполнит:

```
new_block[0] = sequence[0];
new_block[1] = sequence[1];
```

Получим:

```
new_block = {1, 2}
```

Когда `i == 1`:

```
new_block[0] = sequence[1];
new_block[1] = sequence[2];
```

Получим:

```
new_block = {2, 1}
```

И так далее.

Почему мы копируем блок в отдельную память?

Потому что нам необходимо сохранить его в массиве `blocks`, чтобы позднее сравнивать с другими блоками.

Если бы мы просто сохраняли адрес элемента исходной последовательности, то не получили бы независимого массива блока.

## **Шаг 7. Подготовка поиска блока**

```
size_t block_index = block_count;
```

Создаём переменную `block_index`.

В ней будет храниться индекс блока, если мы найдём совпадение.

Почему изначально присваиваем `block_count`?

Потому что если блок не найден, мы будем добавлять его в конец массива.

Индекс следующего свободного элемента равен `block_count`.

## **Шаг 8. Поиск совпадающего блока**

```
for (size_t j = 0; j < block_count; j++)
{
```

Проходим по всем блокам, которые уже были сохранены.

```
if (memcmp(blocks[j].block, new_block, order * sizeof(size_t)) == 0)
```

Здесь используется функция `memcmp`.

Она сравнивает два участка памяти побайтно.

В нашем случае сравниваются:

- уже сохранённый блок `blocks[j].block`;
- новый блок `new_block`.

Третий аргумент указывает количество сравниваемых байтов.

Например, если блок состоит из двух элементов типа `size_t`, сравниваем:

```
2 * sizeof(size_t)
```

Почему условие заканчивается на `== 0`?

Потому что `memcmp` возвращает ноль, если сравниваемые участки памяти полностью совпадают.

Если блоки одинаковые:

```
blocks[j].block = {1, 2}
new_block       = {1, 2}
```

то условие выполнится.

```
block_index = j;
break;
```

Запоминаем индекс найденного блока и завершаем поиск.

Нам больше не нужно проверять остальные элементы массива.

## **Шаг 9. Если блок уже существует**

```
if (block_index < block_count)
{
```

Проверяем, был ли найден совпадающий блок.

Если `block_index` меньше `block_count`, значит, совпадение найдено.

```
blocks[block_index].count++;
```

Увеличиваем частоту найденного блока.

Например, если блок `{1, 2}` уже встречался два раза, теперь его частота станет равна трём.

```
free(new_block);
```

Освобождаем память нового блока.

Почему?

Потому что такой блок уже хранится в массиве `blocks`.

Нам не нужно создавать вторую копию одинакового блока. Достаточно увеличить его счётчик.

Это важный момент управления памятью.

## **Шаг 10. Если блок новый**

```
else
{
```

Если блок не найден, его необходимо добавить в массив.

Но перед добавлением проверяем, хватает ли места.

```
if (block_count == block_capacity)
{
```

Если количество записанных блоков равно вместимости массива, свободного места нет.

Поэтому увеличиваем вместимость.

```
size_t new_capacity;
```

Создаём переменную для новой вместимости массива.

```
if (block_capacity == 0) new_capacity = 4;
```

Если массив ещё не создавался, выделяем место для четырёх структур.

```
else
{
    if (block_capacity > SIZE_MAX / 2)
    {
        free(new_block);
        goto cleanup;
    }

    new_capacity = block_capacity * 2;
}
```

Если массив уже существует, увеличиваем его вместимость в два раза.

Перед умножением проверяем, не приведёт ли оно к переполнению `size_t`.

Если приведёт, освобождаем временный блок и переходим к очистке.

Теперь:

```
if (new_capacity > SIZE_MAX / sizeof(BlockFrequency))
{
    free(new_block);
    goto cleanup;
}
```

Проверяем, не переполнится ли размер памяти при умножении количества структур на размер одной структуры.

Далее выделяем память:

```
BlockFrequency *temp = realloc(
    blocks,
    new_capacity * sizeof(BlockFrequency)
);
```

`realloc` изменяет размер уже выделенного массива.

Мы используем временный указатель `temp`, чтобы не потерять старый адрес `blocks`, если операция завершится ошибкой.

```
if (temp == NULL)
{
    free(new_block);
    goto cleanup;
}
```

Если память не выделилась, освобождаем временный блок и переходим к общей очистке.

Если всё прошло успешно:

```
blocks = temp;
block_capacity = new_capacity;
```

Обновляем указатель на массив и его вместимость.

Теперь можно записывать новый блок.

```
blocks[block_index].block = new_block;
```

Сохраняем адрес выделенной памяти с элементами нового блока.

Обрати внимание: здесь мы не освобождаем `new_block`, потому что теперь его адрес хранится в структуре `blocks`.

```
blocks[block_index].count = 1;
```

Устанавливаем частоту нового блока равной единице.

Почему единице?

Потому что мы только что впервые встретили этот блок.

```
block_count++;
```

Увеличиваем количество уникальных блоков.

На этом обработка одной позиции завершена.

Цикл продолжает работу со следующей позицией и формирует следующий блок.

# **5. Расчёт блочной энтропии**

Когда цикл формирования блоков завершился, у нас уже есть массив уникальных блоков и их частот.

Теперь можно рассчитывать энтропию.

```
double entropy = 0.0;
```

Создаём переменную для накопления результата.

```
for (size_t i = 0; i < block_count; i++)
{
```

Проходим по всем уникальным блокам.

```
double probability = (double)blocks[i].count / (double)total;
```

Рассчитываем вероятность появления текущего блока.

Например, если блок встретился три раза, а всего мы сформировали пять блоков:

\\[ p=\frac35=0.6 \\]

Зачем используем `(double)`?

Чтобы выполнить деление с плавающей точкой.

Без преобразования типов при делении целых чисел мы могли бы потерять дробную часть.

```
entropy -= probability * log2(probability);
```

Это основная математическая операция функции.

Используем формулу энтропии Шеннона:

\\[ B_k=-\sum_i p_i\log_2(p_i) \\]

Каждое слагаемое добавляется к накопленному значению `entropy`.

После завершения цикла получаем общую блочную энтропию.

```
*result = entropy;
```

Записываем результат по адресу, который передал вызывающий код.

# **6. Освобождение памяти**

Теперь необходимо освободить всю динамически выделенную память.

```
for (size_t i = 0; i < block_count; i++)
{
    free(blocks[i].block);
}
```

Проходим по всем уникальным блокам и освобождаем память каждого блока.

Почему нельзя просто написать `free(blocks)`?

Потому что `blocks` — это массив структур, внутри которых находятся указатели на отдельные динамические массивы.

Освобождение внешнего массива не освобождает внутренние блоки.

Поэтому сначала освобождаем каждый блок, а затем внешний массив:

```
free(blocks);
```

После этого:

```
return 0;
```

Функция завершилась успешно.

# **7. Что происходит при ошибке**

В конце функции есть специальная метка:

```
cleanup:
```

Она используется вместе с командой:

```
goto cleanup;
```

Например, если не удалось выделить память для очередного блока, мы переходим сюда.

```
for (size_t i = 0; i < block_count; i++)
{
    free(blocks[i].block);
}
```

Освобождаем все блоки, которые успели сохранить до возникновения ошибки.

```
free(blocks);
```

Освобождаем сам массив структур.

```
return -1;
```

Сообщаем вызывающему коду, что функция завершилась с ошибкой.

Зачем мы сделали отдельный блок `cleanup`?

Чтобы не повторять один и тот же код освобождения памяти после каждой возможной ошибки.

Это особенно полезно в C, когда функция использует много динамически выделяемых массивов.

# **8. Важная дополнительная проверка**

Есть ещё одна техническая деталь, которую стоит добавить в функцию.

Перед выделением памяти:

```
size_t *new_block = malloc(order * sizeof(size_t));
```

нужно проверить, не переполнится ли произведение `order * sizeof(size_t)`.

Поэтому непосредственно перед основным циклом добавь:

```
if (order > SIZE_MAX / sizeof(size_t))
{
    goto cleanup;
}
```

Так мы защитимся от некорректного размера выделяемой памяти.

# **10. Что важно понять перед самостоятельной работой**

Сравним две функции, которые мы уже реализовали:

| `conditional_entropy`                            | `block_entropy`                            |
| ------------------------------------------------ | ------------------------------------------ |
| `ContextFrequency`                               | `BlockFrequency`                           |
| Хранит контекст                                  | Хранит целый блок                          |

Главное отличие в программной реализации: `block_entropy` проще, потому что нам не нужны вложенные массивы для следующих символов и отдельные подсчёты совместных частот.

**Мой совет:** не пытайся сразу запомнить всю функцию. Самое важное — понять три операции:

1. Формирование нового блока и копирование его элементов.
2. Поиск совпадающего блока через `memcmp` и подсчёт частоты.
3. Расчёт энтропии по полученным частотам.

Когда эти три операции станут понятны, вся функция будет восприниматься гораздо проще.
