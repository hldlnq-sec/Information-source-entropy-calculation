Давай разберём `conditional_entropy` буквально по шагам, как будто мы вместе пишем её с нуля. Я буду объяснять не только **что делает каждая строка**, но и **зачем она нужна**, что хранится в памяти и как программа проходит по последовательности.

В конце разберём небольшой пример вручную, чтобы ты понял, откуда берётся результат.

# **1. Что вообще делает&#x20;**`conditional_entropy`

Наша функция рассчитывает условную энтропию последовательности.

У неё есть два режима:

- `order == 0` — обычная энтропия Шеннона. Мы смотрим только на частоту появления каждого символа.
- `order > 0` — условная энтропия. Мы смотрим, какие символы встречаются после определённых последовательностей предыдущих символов.

Например, возьмём последовательность:

```
A B A B A B
```

При `order == 0` мы просто подсчитываем:

- `A` встретился 3 раза;
- `B` встретился 3 раза.

При `order == 1` мы рассматриваем, что идёт после каждого символа:

- после `A` всегда идёт `B`;
- после `B` всегда идёт `A`.

То есть мы уже учитываем зависимость между соседними символами.

Именно поэтому условная энтропия может быть меньше обычной энтропии.

# **2. Заголовок функции и проверки**

```
int conditional_entropy(const size_t *sequence, size_t length, size_t order, double *result)
{
```

Разберём параметры:

| Параметр   | Значение                                                         |
| ---------- | ---------------------------------------------------------------- |
| `sequence` | Указатель на последовательность символов, представленных числами |
| `length`   | Длина последовательности                                         |
| `order`    | Размер контекста — сколько предыдущих элементов учитываем        |
| `result`   | Указатель, через который вернём рассчитанную энтропию            |

Почему функция возвращает `int`, а не `double`?

Потому что мы возвращаем два разных результата:

- через `return 0` сообщаем, что всё прошло успешно;
- через `result` передаём само значение энтропии.

Если возникла ошибка, возвращаем `-1`.

Теперь проверки:

```
if (sequence == NULL) return -1;
if (length == 0) return -1;
if (order >= length && order != 0) return -1;
if (result == NULL) return -1;
```

**Первая проверка:**

```
if (sequence == NULL) return -1;
```

Проверяем, существует ли последовательность.

Если вместо массива передали `NULL`, работать с ним нельзя.

**Вторая проверка:**

```
if (length == 0) return -1;
```

Нельзя рассчитывать энтропию пустой последовательности.

Почему? Потому что при подсчёте вероятностей нам понадобится делить количество появлений символа на общее количество элементов. Если элементов ноль, получится деление на ноль.

**Третья проверка:**

```
if (order >= length && order != 0) return -1;
```

Представим, что у нас есть 5 элементов, а мы хотим анализировать контекст длиной 5.

Для расчёта условной энтропии нам нужны предыдущие 5 элементов и следующий за ними элемент.

Но в последовательности всего 5 элементов. Следующего элемента нет.

Поэтому `order` должен быть меньше `length`.

Почему здесь есть `order != 0`? Потому что нулевой порядок — отдельный режим, в котором мы рассчитываем обычную энтропию.

**Четвёртая проверка:**

```
if (result == NULL) return -1;
```

Проверяем, существует ли указатель, через который мы должны вернуть результат.

Далее:

```
*result = 0.0;
```

Обнуляем результат.

Здесь звёздочка означает, что мы обращаемся к значению по адресу `result`.

Это полезно, чтобы в случае ошибки в переменной результата не осталось случайное старое значение.

# **3. Подготовка структур для хранения контекстов**

```
ContextFrequency *contexts = NULL;

size_t context_count = 0;
size_t context_capacity = 0;
```

Это один из самых важных участков функции.

Нам необходимо хранить информацию о разных контекстах, которые встречаются в последовательности.

Например, для последовательности:

```
A B A B A B
```

при `order == 1` контекстами будут `A` и `B`.

Но нам недостаточно просто запомнить, что они встречались. Нужно ещё запомнить, какие символы после них появлялись и сколько раз.

Для этого мы используем структуру `ContextFrequency`.

Она содержит:

- сам контекст;
- количество появлений контекста;
- массив следующих за ним символов;
- количество уникальных следующих символов;
- вместимость массива следующих символов.

Теперь три переменные:

```
ContextFrequency *contexts = NULL;
```

Это указатель на массив всех найденных контекстов.

Пока массив не создан, поэтому значение `NULL`.

```
size_t context_count = 0;
```

Количество уже добавленных контекстов.

Например, если мы нашли контексты `A` и `B`, значение будет равно 2.

```
size_t context_capacity = 0;
```

Вместимость массива.

Здесь важно различать:

- `context_count` — сколько элементов реально записано;
- `context_capacity` — сколько элементов помещается в выделенной памяти.

Это два разных понятия.

# **4. Отдельная обработка&#x20;**`order == 0`

```
if (order == 0)
{
```

Если пользователь передал нулевой порядок, мы не должны искать контексты.

Нам нужно рассчитать обычную энтропию Шеннона.

Для этого подсчитаем частоты всех уникальных элементов.

```
SymbolFrequency *frequencies = NULL;

size_t frequency_count = 0;
size_t frequency_capacity = 0;
```

Здесь используется другая структура — `SymbolFrequency`.

Она хранит всего две вещи:

- значение символа;
- количество его появлений.

Например, для последовательности:

```
2 5 2 5 2 7
```

массив частот будет выглядеть примерно так:

| symbol | count |
| ------ | ----- |
| 2      | 3     |
| 5      | 2     |
| 7      | 1     |

Переменные:

- `frequencies` — указатель на массив частот;
- `frequency_count` — количество уникальных символов;
- `frequency_capacity` — вместимость массива.

Переходим к циклу:

```
for (size_t i = 0; i < length; i++)
{
```

Мы проходим по всей последовательности.

`i` — индекс текущего элемента.

```
size_t current_symbol = sequence[i];
```

Сохраняем текущий символ в отдельную переменную.

Например, если `i == 0`, то `current_symbol` будет равен первому элементу последовательности.

```
size_t symbol_index = frequency_count;
```

Создаём переменную, в которой будем хранить индекс найденного символа.

Почему изначально присваиваем `frequency_count`?

Потому что если символ не найдётся, мы будем считать, что его нужно добавить в конец массива.

Индекс следующего свободного места как раз равен `frequency_count`.

Теперь ищем символ:

```
for (size_t j = 0; j < frequency_count; j++)
{
    if (frequencies[j].symbol == current_symbol)
    {
        symbol_index = j;
        break;
    }
}
```

Внутренний цикл проходит по уже записанным уникальным символам.

Сравниваем:

```
frequencies[j].symbol == current_symbol
```

Если нашли совпадение, сохраняем индекс:

```
symbol_index = j;
```

И прекращаем поиск:

```
break;
```

Зачем это нужно?

Чтобы не добавлять один и тот же символ в массив несколько раз.

Теперь:

```
if (symbol_index < frequency_count)
{
    frequencies[symbol_index].count++;
}
```

Если индекс меньше количества записанных элементов, значит, символ уже существует.

Следовательно, просто увеличиваем его счётчик.

Например, символ `2` встретился в четвёртый раз — его `count` увеличится на единицу.

А если символ новый?

```
else
{
```

Тогда нужно добавить его в массив.

Но перед добавлением необходимо убедиться, что в массиве есть свободное место.

```
if (frequency_count == frequency_capacity)
{
```

Если количество элементов равно вместимости, свободного места нет.

Увеличиваем вместимость:

```
size_t new_capacity;

if (frequency_capacity == 0) new_capacity = 4;
else
{
    if (frequency_capacity > SIZE_MAX / 2)
    {
        free(frequencies);
        return -1;
    }

    new_capacity = frequency_capacity * 2;
}
```

Логика простая:

- если массив ещё не создавался, выделяем место для 4 элементов;
- если уже существует, увеличиваем вместимость в два раза.

Почему в два раза?

Так мы не вызываем `realloc` при каждом добавлении нового символа. Это уменьшает количество операций выделения памяти.

Проверка `SIZE_MAX / 2` нужна, чтобы умножение на два не вызвало переполнение типа `size_t`.

Далее:

```
if (new_capacity > SIZE_MAX / sizeof(SymbolFrequency))
{
    free(frequencies);
    return -1;
}
```

Проверяем, не переполнится ли размер памяти при умножении количества элементов на размер одной структуры.

Теперь выделяем память:

```
SymbolFrequency *temp = realloc(frequencies, new_capacity * sizeof(SymbolFrequency));
```

`realloc` изменяет размер уже выделенного блока памяти.

Если старого массива нет, `realloc` работает как `malloc`.

Почему результат записывается во временный указатель `temp`?

Потому что если `realloc` завершится ошибкой, он вернёт `NULL`, а исходный указатель `frequencies` останется действительным.

Если бы мы написали:

```
frequencies = realloc(frequencies, ...);
```

то при ошибке потеряли бы адрес старого блока памяти.

Проверяем результат:

```
if (temp == NULL)
{
    free(frequencies);
    return -1;
}
```

Если память выделить не удалось, освобождаем старый массив и завершаем функцию с ошибкой.

Если всё успешно:

```
frequencies = temp;
frequency_capacity = new_capacity;
```

Обновляем указатель и запоминаем новую вместимость.

Теперь добавляем новый символ:

```
frequencies[symbol_index].symbol = current_symbol;
frequencies[symbol_index].count = 1;

frequency_count++;
```

Записываем значение символа, устанавливаем его частоту равной единице и увеличиваем количество уникальных символов.

Таким образом, мы обработали всю последовательность и получили массив частот.

Теперь рассчитываем энтропию:

```
double entropy = 0.0;
```

Создаём переменную для накопления результата.

```
for (size_t i = 0; i < frequency_count; i++)
{
```

Проходим по всем уникальным символам.

```
double probability = (double)frequencies[i].count / (double)length;
```

Рассчитываем вероятность появления текущего символа.

Например, если символ встретился 3 раза в последовательности длиной 6:

\\[ p=\frac{3}{6}=0.5 \\]

Почему используем `(double)`?

Чтобы деление происходило с дробной частью, а не как целочисленное деление.

Далее:

```
entropy -= probability * log2(probability);
```

Это непосредственно формула энтропии Шеннона:

\\[ H=-\sum_i p_i\log_2(p_i) \\]

Каждое слагаемое прибавляется к общей сумме с отрицательным знаком.

После завершения цикла:

```
*result = entropy;
```

Записываем рассчитанную энтропию по адресу, который передал вызывающий код.

```
free(frequencies);
```

Освобождаем память, выделенную для массива частот.

```
return 0;
```

Возвращаем успешное завершение функции.

Почему здесь нужен `return`?

Потому что после расчёта обычной энтропии нам больше нечего делать. Не нужно переходить к обработке контекстов.

# **5. Обработка контекстов при&#x20;**`order > 0`

Если выполнение дошло до этого места, значит, `order` больше нуля.

```
for (size_t i = order; i < length; i++)
{
```

Начинаем проходить последовательность с индекса `order`.

Почему не с нуля?

Потому что нам необходимо иметь перед текущим символом достаточное количество предыдущих элементов.

Например, при `order == 2` мы не можем начать с первого элемента: у него нет двух предыдущих символов.

Следовательно, первый возможный индекс — 2.

```
size_t context_start = i - order;
size_t next_symbol = sequence[i];
```

Здесь мы определяем:

- `context_start` — индекс начала контекста;
- `next_symbol` — символ, который идёт после этого контекста.

Пример:

```
sequence = { 4, 7, 4, 7, 4, 7 };
order = 2;
```

Когда `i == 2`:

- `context_start == 0`;
- контекст — `{4, 7}`;
- следующий символ — `4`.

Теперь выделяем память под контекст:

```
size_t *new_context = malloc(order * sizeof(size_t));

if (new_context == NULL)
{
    goto cleanup;
}
```

Почему нельзя просто сохранить `sequence + context_start`?

Потому что нам нужно независимо хранить контекст внутри массива `contexts`.

Мы выделяем отдельную память и копируем туда значения.

Если память не выделилась, переходим к очистке уже выделенных ресурсов.

```
for (size_t j = 0; j < order; j++)
{
    new_context[j] = sequence[context_start + j];
}
```

Копируем элементы контекста.

Например:

```
sequence = {4, 7, 4, 7, 4, 7};
order = 2;
i = 2;
```

Получим:

```
new_context = {4, 7};
```

Теперь нужно проверить, встречался ли такой контекст раньше.

```
size_t context_index = context_count;
```

Изначально считаем, что контекст новый, и его место будет в конце массива.

```
for (size_t j = 0; j < context_count; j++)
{
    if (memcmp(contexts[j].context, new_context, order * sizeof(size_t)) == 0)
    {
        context_index = j;
        break;
    }
}
```

Здесь используется `memcmp`.

Эта функция сравнивает два участка памяти побайтно.

Мы сравниваем:

- уже сохранённый контекст;
- новый контекст.

Третий аргумент — количество байтов, которые необходимо сравнить.

Если контексты совпадают, `memcmp` возвращает `0`.

Поэтому условие:

```
memcmp(...) == 0
```

означает, что мы нашли такой же контекст.

Сохраняем его индекс и прекращаем поиск.

## **Что происходит, если контекст новый?**

```
if (context_index == context_count)
{
```

Если индекс остался равен количеству контекстов, значит, совпадений не найдено.

Нужно добавить новый контекст.

Сначала проверяем вместимость:

```
if (context_count == context_capacity)
{
```

Если массив заполнен, расширяем его.

Логика такая же, как в предыдущем блоке:

```
size_t new_capacity;

if (context_capacity == 0) new_capacity = 4;
else
{
    if (context_capacity > SIZE_MAX / 2)
    {
        free(new_context);
        goto cleanup;
    }

    new_capacity = context_capacity * 2;
}
```

Проверяем переполнение и определяем новую вместимость.

```
if (new_capacity > SIZE_MAX / sizeof(ContextFrequency))
{
    free(new_context);
    goto cleanup;
}
```

Проверяем, можно ли выделить память под такое количество структур.

```
ContextFrequency *temp = realloc(contexts, new_capacity * sizeof(ContextFrequency));
```

Расширяем массив контекстов.

```
if (temp == NULL)
{
    free(new_context);
    goto cleanup;
}
```

Если память выделить не удалось, освобождаем временный контекст и переходим к общей очистке.

```
contexts = temp;
context_capacity = new_capacity;
```

Обновляем указатель и вместимость.

Теперь добавляем новый контекст:

```
contexts[context_index].context = new_context;
contexts[context_index].context_count = 0;
contexts[context_index].next_symbols = NULL;
contexts[context_index].next_symbol_count = 0;
contexts[context_index].next_symbol_capacity = 0;

context_count++;
```

Разберём каждую строку.

```
contexts[context_index].context = new_context;
```

Сохраняем указатель на скопированный контекст.

```
contexts[context_index].context_count = 0;
```

Пока устанавливаем количество появлений контекста в ноль.

```
contexts[context_index].next_symbols = NULL;
```

У этого контекста пока нет массива следующих символов.

```
contexts[context_index].next_symbol_count = 0;
contexts[context_index].next_symbol_capacity = 0;
```

Устанавливаем количество следующих символов и вместимость массива в ноль.

```
context_count++;
```

Увеличиваем общее количество сохранённых контекстов.

Обрати внимание: здесь мы **не освобождаем&#x20;**`new_context`.

Почему?

Потому что его адрес уже сохранён внутри `contexts`. Эта память теперь принадлежит нашей структуре.

Если освободить её, мы потеряем данные контекста.

А если контекст уже существовал?

```
else
{
    free(new_context);
}
```

Мы создали временную копию, чтобы сравнить её с существующими контекстами.

Но нашли совпадение, поэтому копия больше не нужна.

Освобождаем её.

# **6. Подсчёт количества появлений контекста**

```
contexts[context_index].context_count++;
```

Теперь увеличиваем количество появлений текущего контекста.

Например, если контекст `{4, 7}` встретился уже второй раз, его `context_count` станет равен 2.

Но нам также нужно учитывать, какие символы встречались после этого контекста.

# **7. Подсчёт следующих символов**

```
size_t symbol_index = contexts[context_index].next_symbol_count;
```

Изначально предполагаем, что следующий символ новый и его нужно добавить в конец массива.

Ищем его:

```
for (size_t j = 0; j < contexts[context_index].next_symbol_count; j++)
{
    if (contexts[context_index].next_symbols[j].symbol == next_symbol)
    {
        symbol_index = j;
        break;
    }
}
```

Проходим по всем следующим символам, которые уже сохранены для текущего контекста.

Если находим совпадение, сохраняем индекс.

Теперь:

```
if (symbol_index < contexts[context_index].next_symbol_count)
{
    contexts[context_index].next_symbols[symbol_index].count++;
}
```

Если символ уже существует, увеличиваем его частоту.

Если не существует:

```
else
{
```

Нужно добавить новую запись.

Проверяем, хватает ли места:

```
if (contexts[context_index].next_symbol_count == contexts[context_index].next_symbol_capacity)
{
```

Если массив заполнен, увеличиваем его вместимость:

```
size_t new_capacity;

if (contexts[context_index].next_symbol_capacity == 0) new_capacity = 4;
else
{
    if (contexts[context_index].next_symbol_capacity > SIZE_MAX / 2)
    {
        goto cleanup;
    }

    new_capacity = contexts[context_index].next_symbol_capacity * 2;
}
```

Здесь всё аналогично предыдущим блокам.

Проверяем размер выделяемой памяти:

```
if (new_capacity > SIZE_MAX / sizeof(SymbolFrequency))
{
    goto cleanup;
}
```

Выделяем память:

```
SymbolFrequency *temp = realloc(
    contexts[context_index].next_symbols,
    new_capacity * sizeof(SymbolFrequency)
);
```

Если произошла ошибка:

```
if (temp == NULL)
{
    goto cleanup;
}
```

Если всё успешно:

```
contexts[context_index].next_symbols = temp;
contexts[context_index].next_symbol_capacity = new_capacity;
```

Обновляем указатель и вместимость.

Теперь добавляем новую запись:

```
contexts[context_index].next_symbols[symbol_index].symbol = next_symbol;
contexts[context_index].next_symbols[symbol_index].count = 1;

contexts[context_index].next_symbol_count++;
```

Сохраняем новый символ, устанавливаем частоту 1 и увеличиваем количество уникальных следующих символов.

В итоге для каждого контекста у нас есть собственный массив следующих символов и их частот.

# **8. Расчёт условной энтропии**

После завершения основного цикла мы собрали все необходимые частоты.

```
size_t total = length - order;
double entropy = 0.0;
```

`total` — количество наблюдений, для которых у нас есть контекст и следующий символ.

Почему `length - order`?

Потому что первые `order` элементов не могут быть целевыми символами: перед ними ещё недостаточно элементов для формирования контекста.

Теперь:

```
for (size_t i = 0; i < context_count; i++)
{
    for (size_t j = 0; j < contexts[i].next_symbol_count; j++)
    {
```

У нас два вложенных цикла.

Внешний проходит по всем контекстам.

Внутренний проходит по всем следующим символам конкретного контекста.

Например:

| Контекст | Следующий символ | Частота |
| -------- | ---------------- | ------- |
| A        | B                | 3       |
| B        | A                | 2       |
| B        | C                | 1       |

Мы обрабатываем каждую строку отдельно.

```
size_t joint_count = contexts[i].next_symbols[j].count;
```

Получаем совместную частоту контекста и следующего символа.

Например, если после контекста `B` символ `A` встретился два раза, `joint_count` будет равен 2.

Далее:

```
double p_joint = (double)joint_count / (double)total;
```

Вычисляем совместную вероятность:

\\[ p(c,a)=\frac{n(c,a)}{N-order} \\]

Затем:

```
double p_conditional = (double)joint_count / (double)contexts[i].context_count;
```

Вычисляем условную вероятность следующего символа при известном контексте:

\\[ p(a|c)=\frac{n(c,a)}{n(c)} \\]

И наконец:

```
entropy -= p_joint * log2(p_conditional);
```

Это основное математическое действие всей функции.

Мы суммируем:

\\[ H=-\sum\_{c,a}p(c,a)\log_2 p(a|c) \\]

После завершения двух циклов получаем итоговую условную энтропию.

```
*result = entropy;
```

Записываем результат вызывающему коду.

# **9. Освобождение памяти**

Это обязательная часть работы с динамической памятью в C.

```
for (size_t i = 0; i < context_count; i++)
{
    free(contexts[i].context);
    free(contexts[i].next_symbols);
}
```

Для каждого сохранённого контекста освобождаем:

1. память, в которой хранится сам контекст;
2. память, в которой хранится массив следующих символов.

Почему недостаточно просто написать `free(contexts)`?

Потому что массив `contexts` содержит указатели на другие выделенные блоки памяти.

Освобождение внешнего массива не освобождает память, на которую указывают эти указатели.

Поэтому сначала освобождаем внутренние массивы, а потом внешний:

```
free(contexts);
```

И возвращаем успешный результат:

```
return 0;
```

# **10. Что такое&#x20;**`cleanup`**&#x20;и зачем нужен&#x20;**`goto`

В конце функции есть ещё один участок:

```
cleanup:

    for (size_t i = 0; i < context_count; i++)
    {
        free(contexts[i].context);
        free(contexts[i].next_symbols);
    }

    free(contexts);

    return -1;
```

Это специальная точка, куда программа переходит, если во время выделения памяти произошла ошибка.

Например:

```
if (new_context == NULL)
{
    goto cleanup;
}
```

Команда `goto cleanup` буквально означает: перейти к метке `cleanup`.

Почему это удобно?

Представим, что у нас уже создано 5 контекстов, и на шестом произошла ошибка выделения памяти.

Нам необходимо освободить все 5 контекстов и их внутренние массивы.

Вместо того чтобы писать один и тот же код очистки после каждой ошибки, мы направляем выполнение в одно место.

Это позволяет избежать утечек памяти и не дублировать код.

| Контекст | Следующий символ |
| -------- | ---------------- |
| 1        | 2                |
| 2        | 1                |

**Итоговые частоты**

| Контекст | Следующий символ | Частота |
| -------- | ---------------- | ------- |
| 1        | 2                | 3       |
| 2        | 1                | 2       |

Последний элемент не рассматривается как контекст, поскольку после него нет следующего символа.

Теперь вероятности:

\\[ p(1,2)=\frac{3}{5},\qquad p(2,1)=\frac{2}{5} \\]

Условные вероятности:

\\[ p(2|1)=\frac{3}{3}=1 \\]

\\[ p(1|2)=\frac{2}{2}=1 \\]

Подставляем в формулу:

\\[ H=-\frac35\log_2 1-\frac25\log_2 1=0 \\]

Получаем **нулевую условную энтропию**.

Почему ноль? Потому что, зная предыдущий символ, мы точно знаем следующий.

# **13. Переходим к следующей функции**

По порядку исходной Python-программы следующая функция — `block_entropy`. Она также присутствует в приложении А курсового проекта.&#x20;

Она рассчитывает **блочную энтропию** — энтропию последовательностей, состоящих из нескольких элементов.

Важно не путать её с условной энтропией:

- `conditional_entropy` анализирует вероятность следующего символа при известном предыдущем контексте;
- `block_entropy` рассматривает целые блоки фиксированной длины как отдельные элементы нового алфавита.

Например, есть последовательность:

```
1 2 1 2 1 2
```

Если длина блока равна 2, мы получаем блоки:

```
(1, 2)
(2, 1)
(1, 2)
(2, 1)
(1, 2)
```

Затем подсчитываем частоты этих блоков:

| Блок   | Частота |
| ------ | ------- |
| (1, 2) | 3       |
| (2, 1) | 2       |

И уже по этим частотам рассчитываем обычную энтропию Шеннона.
