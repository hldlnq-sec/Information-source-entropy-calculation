## **1. Для чего нужна&#x20;**`tokenize_python_source()`**?**

Входные данные функции — уже декодированный текст Python-файла:

```
const DecodedText *text
```

В `DecodedText` содержатся Unicode-символы типа `uint32_t`, а не исходные UTF-8-байты.

Результат:

```
TokenSequence *result
```

Это динамический массив токенов. Каждый токен содержит:

- `symbols` — символы, из которых состоит токен;
- `length` — количество символов;
- `type` — категория токена.

Например, исходный код:

```
total = price + 10
```

После токенизации должен дать примерно такую последовательность:

| Содержимое | Тип                |
| ---------- | ------------------ |
| `total`    | `TOKEN_IDENTIFIER` |
| `=`        | `TOKEN_OPERATOR`   |
| `price`    | `TOKEN_IDENTIFIER` |
| `+`        | `TOKEN_OPERATOR`   |
| `10`       | `TOKEN_NUMBER`     |
| `NEWLINE`  | `TOKEN_NEWLINE`    |

Обрати внимание: пробелы в этой последовательности отсутствуют, потому что мы решили не учитывать их как самостоятельные токены.

При этом переводы логических строк сохраняются в виде структурного токена `NEWLINE`.

## **2. Общая схема работы функции**

**DecodedText**

Входная последовательность Unicode-символов

**tokenize_python_source()**

Последовательный анализ символов

**Идентификаторы**

Имена переменных, функций

**Числа**

Числовые литералы

**Строки**

Обычные и многострочные

**Операторы**

Включая составные

**TokenSequence**

Готовая последовательность токенов

Внутри функции мы будем двигаться по массиву `text->symbols` при помощи индекса `i`.

Главный принцип: на каждой итерации определяем, какой элемент начинается с текущей позиции, устанавливаем его тип, определяем длину и добавляем его в результат.

## **3. Разбираем начало функции**

Начнём с заголовка:

```

Мы используем указатель на результат, поскольку функция должна изменять его содержимое.

### **Проверка входных аргументов**

```
if (text == NULL) return -1;
if (result == NULL) return -1;

if (text->length > 0 && text->symbols == NULL)
{
    return -1;
}
```

Разберём условия.

**Первое и второе:**

```
if (text == NULL) return -1;
if (result == NULL) return -1;
```

Не допускаем передачу нулевых указателей.

Если `text == NULL`, мы не можем получить доступ к исходной последовательности.

Если `result == NULL`, мы не можем записывать результат.

**Третье:**

```
if (text->length > 0 && text->symbols == NULL)
{
    return -1;
}
```

Здесь проверяется согласованность структуры `DecodedText`.

Например:

```
DecodedText text = {

    .length = 10
};
```

Такая структура некорректна: указано, что в ней десять символов, но память для них отсутствует.

А вот пустой текст допустим:

```
DecodedText text = {
    .symbols = NULL,
    .length = 0
};
```

В этом случае токенизатор должен успешно вернуть пустую последовательность.

Мы договорились, что функция принимает только пустой `TokenSequence`.

## **4. Основной цикл токенизатора**

В старой реализации у тебя было:

```
size_t i = 0;

while (i < text->length)
{
    uint32_t symbol = text->symbols[i];

    // Обработка символа
}
```

Это центральная конструкция всей функции.

`i` — индекс текущего символа.

`text->length` — общее количество символов.

Например, для строки:

```
x = 25
```

Последовательность будет выглядеть так:

| Индекс `i` | Символ |
| ---------- | ------ |
| 0          | `x`    |
| 1          | пробел |
| 2          | `=`    |
| 3          | пробел |
| 4          | `2`    |
| 5          | `5`    |

В начале:

```
size_t i = 0;
```

Мы устанавливаем позицию на первый символ.

Затем:

```
while (i < text->length)
```

Цикл работает, пока не достигнет конца текста.

И наконец:

```
uint32_t symbol = text->symbols[i];
```

Получаем текущий Unicode-символ.

Почему `uint32_t`, а не `char`?

Потому что после декодирования UTF-8 в `DecodedText` у нас находятся Unicode code points. Один такой символ может занимать несколько байтов в исходном файле, но здесь представлен одним значением `uint32_t`.

## **1. Почему нельзя просто пропускать все пробелы**

В старой версии функции было условие:

```
if (symbol == ' ' || symbol == '\t' ||
    symbol == '\n' || symbol == '\r' ||
    symbol == '\f')
{
    i++;
    continue;
}
```

Оно пропускало все пробельные символы. Для простого выделения слов этого достаточно, но для Python есть проблема.

Посмотри на пример:

```
if temperature > 20:    print("Warm")    print("Sunny")print("Cold")
```

Отступы здесь определяют вложенность команд. А переводы строк отделяют логические инструкции.

Поэтому нам нужно различать:

- пробелы и табуляции в начале строки — они участвуют в определении отступа;
- пробелы между токенами — их можно пропускать;
- перевод строки — иногда он должен создавать `TOKEN_NEWLINE`;
- перевод строки внутри скобок — не должен завершать логическую инструкцию;
- комментарий — пропускается до конца физической строки.

## **2. Добавим состояние токенизатора**

Для этого нам понадобятся несколько переменных, которые будут хранить состояние обработки исходного кода.

Предлагаю после `size_t i = 0;`, но перед `while`, добавить:

```
size_t indentation_stack[256];
size_t indentation_level = 0;

int at_line_start = 1;
int logical_line_has_code = 0;
size_t bracket_level = 0;
```

Разберём каждую.

`indentation_stack` — стек уровней отступов. Например, для кода:

```
if condition:    if another_condition:        print("Hello")
```

стек будет постепенно хранить значения отступов: `0`, `4`, `8`.

`indentation_level` — количество уровней, которые сейчас находятся в стеке.

`at_line_start` — показывает, находимся ли мы в начале физической строки. Это важно, чтобы отличать отступы от пробелов внутри инструкции.

`logical_line_has_code` — показывает, встретили ли мы уже код в текущей логической строке. Это позволит не создавать лишние `NEWLINE` для пустых строк и строк с комментариями.

`bracket_level` — количество незакрытых скобок. Если оно больше нуля, перевод строки не завершает логическую инструкцию.

Например:

```
result = calculate(    first_value,    second_value)
```

Здесь физически четыре строки, но логически это одна инструкция.

> Пока используем фиксированный стек на 256 уровней. Позже можно обсудить динамический стек, но для учебной реализации сначала проще сделать фиксированный.

## **3. Обработка пробелов и табуляции**

В начале физической строки пробелы и табуляции определяют уровень отступа.

Правило для табуляции, которое мы приняли: табуляция перемещает позицию к ближайшему числу, кратному восьми.

Например:

| Текущая позиция | Символ    | Новая позиция |
| --------------- | --------- | ------------- |
| 0               | пробел    | 1             |
| 1               | пробел    | 2             |
| 2               | табуляция | 8             |
| 8               | пробел    | 9             |
| 9               | табуляция | 16            |

В C это можно вычислять так:

```
if (symbol == ' ')
{
    indentation++;
}
else if (symbol == '\t')
{
    indentation = ((indentation / 8) + 1) * 8;
}
```

Здесь `indentation` — переменная, которую мы будем использовать для подсчёта отступа текущей строки.

Но важно: этот код должен выполняться только в начале физической строки. Если пробел встретился между `total` и `=`, он не должен влиять на отступ.

## **4. Обработка комментариев**

Комментарий в Python начинается с `#` и продолжается до конца физической строки:

```
total = 10  # Initial value
```

Когда токенизатор встречает `#`, он должен пропустить все символы до `\n` или конца входной последовательности.

Принципиально это выглядит так:

```
if (symbol == '#')
{
    while (i < text->length &&
           text->symbols[i] != '\n')
    {
        i++;
    }

    continue;
}
```

Обрати внимание на `continue`: после пропуска комментария мы возвращаемся к началу основного цикла.

При этом сам перевод строки мы пока не пропускаем — его нужно обработать отдельно, чтобы при необходимости сформировать `TOKEN_NEWLINE`.

# **Этап 1. Разбираемся с физическими и логическими строками**

В Python необходимо различать два понятия.

**Физическая строка** — строка исходного файла, заканчивающаяся символом перевода строки `\n`.

**Логическая строка** — законченная инструкция Python. Она может занимать одну или несколько физических строк.

Например:

```
total = 10price = 20result = total + price
```

Здесь три физические и три логические строки.

А теперь другой пример:

```
result = calculate(    first_value,    second_value)
```

Здесь четыре физические строки, но одна логическая инструкция.

Почему это важно? Потому что мы договорились добавлять специальный токен `TOKEN_NEWLINE` только в конце логической инструкции, а не после каждого физического перевода строки.

# **Этап 2. Для чего нужна переменная bracket_level**

В предыдущем сообщении мы добавили:

```
size_t bracket_level = 0;
```

Она будет отслеживать, находимся ли мы внутри незакрытых скобок.

Рассмотрим:

```
result = calculate(    first_value,    second_value)
```

Когда токенизатор встретит открывающую круглую скобку `(`, увеличим значение:

```
bracket_level++;
```

Когда встретит закрывающую `)`, уменьшим:

```
bracket_level--;
```

Аналогично учитываем квадратные `[]` и фигурные `{}` скобки.

Получается следующая логика:

| Встреченный символ | bracket_level |
| ------------------ | ------------- |
| Начало файла       | 0             |
| `(`                | 1             |
| Перевод строки     | 1             |
| `[`                | 2             |
| `]`                | 1             |
| Перевод строки     | 1             |
| `)`                | 0             |
| Перевод строки     | 0             |

Таким образом, если `bracket_level > 0`, перевод строки не завершает логическую инструкцию.

**Важное замечание:** пока мы только проектируем механизм. Позже при обработке операторов нужно будет не допустить уменьшения счётчика ниже нуля и корректно обрабатывать несогласованные скобки.

Первое:

```

Мы не находимся внутри незакрытых скобок.

Второе:

```
logical_line_has_code
```

В текущей логической инструкции уже встречался хотя бы один токен.

Почему нужна вторая проверка?

Посмотри на код:

```

```

Пустые строки и строки, состоящие только из комментариев, не должны создавать лишние `TOKEN_NEWLINE`.

### **3.3. Добавляем структурный токен**

```
if (append_special_token(result, TOKEN_NEWLINE) != 0)
{
    goto cleanup;
}
```

Здесь используем нашу вспомогательную функцию `append_special_token()`.

Она должна добавлять специальный токен без массива символов.

Например, для `TOKEN_NEWLINE`:

- `type` будет равен `TOKEN_NEWLINE`;
- `symbols` будет равен `NULL`;
- `length` будет равен `0`.

Если добавление завершилось ошибкой, переходим к общей очистке памяти.

### **3.4. Сбрасываем состояние логической строки**

```
logical_line_has_code = 0;
```

Мы завершили логическую инструкцию.

Следовательно, следующая инструкция должна начинаться с нового состояния.

### **3.5. Отмечаем начало физической строки**

```
at_line_start = 1;
```

Это очень важно.

Теперь следующий символ будет рассматриваться как начало новой физической строки. Если после него встретятся пробелы или табуляции, они могут определять уровень отступа.

### **3.6. Переходим к следующему символу**

```
i++;
continue;
```

Увеличиваем индекс, чтобы не обрабатывать тот же `\n` повторно.

`continue` возвращает нас к началу `while`.

## **1. Какую задачу мы решаем**

Рассмотрим пример:

```
def calculate():    if True:        result = 10    return resultprint(calculate())

Токенизатор должен определить три уровня отступов:

- `0` — основной уровень;
- `4` — тело функции;
- `8` — тело условия.

Когда начинается блок с большим отступом, добавляется `TOKEN_INDENT`.

Когда мы возвращаемся к меньшему отступу, добавляется один или несколько `TOKEN_DEDENT`.

## **2. Вспоминаем наш стек отступов**

Ранее мы добавили:

```

Здесь `indentation_stack` хранит значения отступов, а `indentation_level` показывает количество уровней.

Почему `1`, а не `0`?

Потому что в стеке уже находится один элемент — начальный уровень `0`.
